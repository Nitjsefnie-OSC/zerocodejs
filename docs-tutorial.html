はじめての組み込み

ZeroCode.js をインストールしてから、最初のページを公開するまでを、順を追って説明します。最後まで進めると、「開発者がパーツを書く → 運営者が管理画面でページを作る → 公開ページに表示される」という一連の流れが、手元で動きます。

必要なもの: Node.js 20 以上、テキストエディタ（VS Code がおすすめ）。所要時間は30分ほどです。完成形に近いものは、リポジトリの examples/lp で動かせます。

全体像

ZeroCode.js に関わる人は、次の4者です。ZeroCode.js が受け持つのは管理画面と HTML を作る部分だけで、データの保存やログインは、あなたのサーバー（ホスト）が受け持ちます。

誰が 何をする 使うもの
開発者 ページの部品（パーツ）を HTML で書く 手元のエディタ、npx zerocodejs
ホスト パーツとページのデータを保存し、管理画面に渡す。公開ページの HTML を返す あなたのサーバー（このページでは Node.js + Express）
運営者 パーツを並べて文章・画像を入れ、ページを作る 管理画面（<zcode-cms>）
訪問者 公開ページを見る ふつうの HTML（ZeroCode.js の読み込みは不要）

覚える言葉は4つ

パーツ: 書いた HTML が、そのまま入力欄になる

パーツは、見出し・カード・お問い合わせ欄などのページの部品です。開発者がふつうの HTML で書き、運営者に入力してほしいところだけを {$名前:初期値} のような記法にします。管理画面は、この記法から入力欄を自動で作ります。

ページ: パーツを並べたもの

ページは、パーツを上から順に並べ、それぞれに入力した内容を持たせたものです。データとしては、「どのパーツを使い、何を入力したか」の一覧（JSON）だけを保存します。HTML は表示のたびにパーツから作り直すので、パーツの見た目を直すと、そのパーツを使っているすべてのページに反映されます。

カテゴリ: 共通・個別・専用

パーツと画像は、どこで使うかによって3つのカテゴリに分けます。

共通

サイト全体で使う。見出し・ボタン・お問い合わせ欄など。

個別

ページの種類ごとに使う。店舗ページ用・記事ページ用など。

専用

特定のページや用途のためだけに作る。キャンペーンページの特別な部品など。

最初は「共通」だけで十分です。このページでも、共通のパーツを1つ作ります。

画面: 使う人に合わせて3つ

<zcode-cms>

運営者向け。パーツの追加・編集・並べ替え・削除だけができる。パーツ自体は変えられない。

<zcode-editor>

開発者向け。cms の機能に加えて、パーツ管理・画像管理・データの確認ができる。

<zcode-studio>

専用パーツの担当者向け。パーツ管理などで扱えるのは専用カテゴリだけ。

このページでは、運営者の画面 <zcode-cms> を使います。

手順

次の6つの手順で、図1の①〜④を順に作ります。できあがるフォルダは次のとおりです。

my-site/
├── parts/                      手順2: パーツ（開発者が書く）
│   └── common/01-heading/
│       ├── _type.json
│       ├── 01-heading.html
│       └── 01-heading.css
├── data/
│   ├── parts.json              手順3: build-parts が作る（自動生成）
│   └── page.json               管理画面から保存したページ
├── public/admin.html           手順5: 管理画面
├── server.js                   手順4: サーバー
└── package.json

1. インストール

mkdir my-site && cd my-site
npm init -y
npm pkg set type=module
npm install zerocodejs express jsdom
npx zerocodejs init-vscode
  • express はこのページで使うサーバーです。お使いのものに置き換えられます。
  • jsdom は、サーバーで HTML を作る（手順4）ときに使います。
  • init-vscode は、VS Code で記法の補完を出す設定を .vscode/ に置きます（エディタの補完）。

2. 最初のパーツを書く

見出しとリード文のパーツを1つ作ります。フォルダ名・ファイル名の先頭の番号は、管理画面に並ぶ順番です。

parts/common/01-heading/_type.json（パーツのグループ。「タイプ」と呼びます） 

{ "id": "type-heading", "type": "見出し", "description": "セクションの見出し" }

parts/common/01-heading/01-heading.html（パーツ本体）

<!--zerocode
{ "id": "heading", "title": "見出し", "description": "セクションの見出しとリード文" }
-->
<section class="heading">
  <h2 z-tag="$tag:h2|h3">{$title:見出しを入力}</h2>
  <p z-empty="$lead">{$lead?:リード文を入力:textarea}</p>
</section>

parts/common/01-heading/01-heading.css（パーツの CSS。なくてもよい）

.heading { padding: 48px 16px; text-align: center; }

使った記法は次の4つです。

記法 管理画面での見え方
{$title:見出しを入力} 1行の入力欄。初期値は「見出しを入力」
{$lead?:…:textarea} 複数行の入力欄。? は「空でもよい」
z-tag="$tag:h2|h3" 見出しのタグを h2 / h3 から選べる
z-empty="$lead" リード文が空なら、この <p> ごと出力しない

パーツの先頭のコメント（<!--zerocode … -->）の id は、ページのデータから参照されます。一度使い始めたら変えないでください。記法の一覧はテンプレート記法にあります。

3. パーツを1つの JSON にまとめる

npx zerocodejs check-parts parts               # 書き間違いを調べる
npx zerocodejs build-parts parts -o data/parts.json

data/parts.json に、管理画面とサーバーが読む形（{ parts, css }）のデータができます。パーツを書いている間は --watch を付けると、保存のたびに作り直されます。 

npx zerocodejs build-parts parts -o data/parts.json --watch

4. サーバーを用意する

サーバーの役目は3つです。管理画面にデータを渡すこと、保存すること、公開ページの HTML を返すことです。

server.js

import express from 'express';
import { readFileSync, writeFileSync, existsSync } from 'node:fs';
import { renderToHtml, renderCssToHtml } from 'zerocodejs/ssr';

const app = express();
app.use(express.json({ limit: '10mb' }));

const readJson = (file, fallback) =>
  existsSync(file) ? JSON.parse(readFileSync(file, 'utf8')) : fallback;

// パーツ（build-parts の出力）と、保存したページを合わせて ZeroCode のデータにする
function loadData() {
  const { parts, css } = readJson('data/parts.json', { parts: {}, css: {} });
  const saved = readJson('data/page.json', { page: [], images: {} });
  return {
    page: saved.page,
    parts: { common: [], individual: [], special: [], ...parts },
    css,
    images: { common: [], individual: [], special: [], ...saved.images }
  };
}

// 管理画面: データを渡す・保存する（本番では、ここをログインで守る）
app.get('/api/data', (req, res) => res.json(loadData()));
app.post('/api/save', (req, res) => {
  const { page, images } = req.body;
  writeFileSync('data/page.json', JSON.stringify({ page, images }, null, 2));
  res.json({ ok: true });
});

// 公開ページ: サーバーで HTML を作る
app.get('/', (req, res) => {
  const data = loadData();
  res.send(`<!doctype html>
<html lang="ja">
<head><meta charset="utf-8">${renderCssToHtml(data.css)}</head>
<body>${renderToHtml(data)}</body>
</html>`);
});

app.use(express.static('public'));
app.use('/vendor/vue', express.static('node_modules/vue/dist'));
app.use('/vendor/zerocodejs', express.static('node_modules/zerocodejs/dist'));

app.listen(3000, () => console.log('http://localhost:3000'));

ポイント: 保存するのはページ（page）と画像だけです。パーツはファイルが正本なので、管理画面からは保存しません。データの形はデータ構造にあります。

5. 管理画面を作る

管理画面は、<zcode-cms> を置き、データを渡し、保存の合図を受け取るだけです。

public/admin.html

<!doctype html>
<html lang="ja">
  <head>
    <meta charset="utf-8" />
    <title>管理画面</title>
    <link rel="stylesheet" href="/vendor/zerocodejs/zerocodejs.css" />
  </head>
  <body>
    <zcode-cms id="cms" locale="ja"></zcode-cms>

    <script src="/vendor/vue/vue.global.prod.js"></script>
    <script src="/vendor/zerocodejs/zerocode.umd.js"></script>
    <script>
      const cms = document.getElementById('cms');

      // 1. データを読み込んで渡す
      fetch('/api/data')
        .then((res) => res.json())
        .then((data) => {
          cms.setAttribute('parts-common', JSON.stringify(data.parts.common));
          cms.setAttribute('css-common', data.css.common || '');
          cms.setAttribute('images-special', JSON.stringify(data.images.special));
          cms.setAttribute('page', JSON.stringify(data.page));
        });

      // 2. 保存ボタンが押されたら、データを取り出してサーバーに送る
      cms.addEventListener('save-request', async (event) => {
        const { requestId, targets } = event.detail;
        const data = cms.getData();
        const res = await fetch('/api/save', {
          method: 'POST',
          headers: { 'Content-Type': 'application/json' },
          body: JSON.stringify({ page: data.page, images: data.images })
        });
        // 3. 結果を知らせる（管理画面に「保存しました」などが出る）
        for (const target of targets) {
          cms.dispatchEvent(
            new CustomEvent('save-result', {
              detail: { requestId, target, ok: res.ok, errors: [] }
            })
          );
        }
      });
    </script>
  </body>
</html>

保存のときの流れは次のとおりです。

Vite などのバンドラーを使う場合: <script> での読み込みの代わりに、import 'zerocodejs/cms'; と import 'zerocodejs/style.css'; を書きます（zerocodejs/cms は <zcode-cms> だけの軽い入り口です）。

6. 動かして確かめる

node server.js
  1. http://localhost:3000/admin.html を開き、「+ パーツを追加」から「見出し」を選びます。
  2. 追加した見出しをクリックすると編集パネルが開くので、文字を入れます。
  3. 左下の「保存」を押します。data/page.json にページが保存されます。
  4. http://localhost:3000/ を開くと、入力した見出しが表示されます。ページのソースを見ると、書いた HTML のままで、ZeroCode.js の余計なタグが入っていないことがわかります。

パーツの HTML を直して build-parts をやり直すと、保存済みのページにもそのまま反映されます（図1の①→②→④）。
